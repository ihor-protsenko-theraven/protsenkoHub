# Мобільна збірка protsenkoHub

Вебверсія/PWA та API продовжують розгортатися на Vercel. Android та iOS збираються з того самого Angular-коду через Capacitor і використовують той самий NestJS API. Віджети реалізовані окремо нативним кодом.

## Перед першим запуском

1. Розгорніть API на публічному HTTPS-домені з маршрутами `/api/v1`. Застосуйте міграції бази командою `npm run db:deploy`; мобільні сесії та ревізія сну потребують нових таблиці й колонки.
2. Оберіть остаточні Android application ID, iOS bundle ID застосунку й extension та App Group. Поточні значення `com.protsenko.hub`, `com.protsenko.hub.sleepwidget` і `group.com.protsenko.hub` є робочими. Якщо змінюєте їх, оновіть Capacitor config, Android package/application ID, Xcode build settings, entitlements і Swift `SleepWidgetStore.groupID` разом.
3. На Mac установіть Node.js 22+, Xcode 26+ та Command Line Tools. Для Android установіть Android Studio Quail 4 (2026.1.4) або новішу, SDK API 36 і повний JDK 21 з `jlink`. Проєкт використовує Capacitor 8.5.3, Android Gradle Plugin 9.4.1 і Gradle 9.6; мінімальний Android API — 24.

Публічна HTTPS-адреса вебверсії та API — `https://protsenko-hub.vercel.app`. 25 жовтня 2026 року розгорнуто API з мобільною авторизацією та віджетом і застосовано міграції `mobile_sessions` та `sleep_widget_revision`. На основному домені перевірено: вебсторінка відповідає 200, CORS preflight з `https://localhost` дозволено, невалідний запит до `/api/v1/auth/mobile/login` повертає 400, а запит до `/api/v1/children/sleep/widget` без авторизації — 401. На Android-емуляторі повторний вхід успішний, а екран сну завантажує дані. Вхід з реального телефона та синхронізація віджета потребують окремої перевірки.

## Зібрати та синхронізувати

З кореня репозиторію після `npm ci`:

```powershell
$env:MOBILE_API_ORIGIN = 'https://protsenko-hub.vercel.app'
$env:MOBILE_WEB_ORIGIN = 'https://protsenko-hub.vercel.app'
npm run sync:mobile
```

На Mac експортуйте обидві змінні перед `npm run sync:mobile`. Вказуйте лише корені HTTPS-доменів без `/api/v1`; якщо веб та API мають один домен, обидві змінні мають однакове значення. Команда збирає мобільний Angular з цими адресами та копіює файли в обидва нативні проєкти. Після Windows `cap sync` вона також нормалізує шляхи Swift Package для Xcode. Вебзбірка Vercel використовує свої чинні маршрути й не потребує цих змінних.

Після зміни Angular-коду повторіть `npm run sync:mobile`. Після зміни нативного коду відкрийте `apps/mobile/android` в Android Studio або `apps/mobile/ios/App/App.xcodeproj` у Xcode та перебудуйте застосунок. Нова версія вебсайту не оновлює вбудований код уже встановленого мобільного застосунку.

## Android

На Windows запустіть `npm run sync:mobile:android`, відкрийте `apps/mobile/android` в Android Studio, у налаштуваннях Gradle оберіть повний JDK 21, дочекайтеся Gradle sync, оберіть пристрій або емулятор і запустіть `app`. Також доступна команда `npm run run:mobile:android`. Для збірки з термінала задайте `JAVA_HOME` на корінь JDK 21 і `ANDROID_HOME` на каталог SDK, потім у `apps/mobile/android` виконайте `.\gradlew.bat assembleDebug`. Результат буде в `app/build/outputs/apk/debug/app-debug.apk`. Якщо встановлений APK уже зібрано з адресою https://protsenko-hub.vercel.app, оновлення API не потребує перевстановлення застосунку: закрийте його повністю та спробуйте вхід знову.

Віджет **«Сон дитини»** додається через меню віджетів системи. Під час сну він показує тривалість, початок і кількість пауз; кнопки «Пауза»/«Продовжити», «Зберегти» й «Видалити» працюють без відкриття застосунку. «Зберегти» завершує сон, «Видалити» одразу скасовує поточний запис. Без активного сну віджет показує останній завершений сон і одну кнопку «Почати сон»; тип денного або нічного сну визначає сервер. Перед дією обробник перечитує живий стан з API та звіряє сеанс і ревізію. При конфлікті перечитує стан, при втраті мережі показує помилку. Токен дії зберігається зашифрованим ключем Android Keystore, відображуваний знімок — у приватному сховищі застосунку; обидва видаляються при виході. Час з останнього сну оновлюється за системним розкладом, який може відставати. Нативна debug-збірка на Windows успішно пройшла; перевірка віджета на пристрої ще потрібна.

Перед перевіркою нових кнопок на телефоні розгорніть API з підтримкою дій `start`, `save` і `delete`; попередня серверна версія приймає лише `pause` та `resume`.

Початковий розмір Android-віджета — 2×2 клітинки. Для малого розміру він використовує компактний макет, а після розтягування в обох напрямках показує більші кнопки й текст. Щоб застосувати новий початковий розмір після встановлення оновленого APK, видаліть старий віджет із головного екрана й додайте його знову. Для зміни розміру затисніть картку та перетягніть маркери рамки. Лаунчер телефона визначає фактичний розмір клітинок; вигляд і мінімальну висоту на Samsung потрібно перевірити на пристрої.

## iPhone

На Mac запустіть `npm run sync:mobile:ios` і відкрийте `apps/mobile/ios/App/App.xcodeproj` у Xcode. У Signing & Capabilities для **App** і **SleepWidgetExtension** оберіть свою команду підпису та зареєструйте однакову App Group `group.com.protsenko.hub`. Перевірте обидва bundle ID. Зберіть App на iPhone, додайте малий квадратний віджет **«Сон дитини»**, перевірте перехід до `/app/sleep`, оновлення й вихід з акаунта. На iOS 17+ кнопки «Почати», «Пауза»/«Продовжити», «Зберегти» й «Видалити» виконують App Intent без відкриття застосунку; на iOS 15–16 кнопки відкривають екран сну. Extension читає відображуваний знімок зі спільного UserDefaults, а токен дії — зі спільної Keychain App Group. Якщо App Group не доступна під час запуску, запис знімка поверне помилку. Xcode-компіляція та підпис не перевірені на поточному Windows-хості.

Для TestFlight та App Store потрібен Apple Developer Program. До появи акаунта можливості локального підпису й App Group на конкретному Mac слід перевірити в Xcode.

## Що перевірити на телефонах

- Вхід двох батьків, повторний запуск, протермінування access token, ротацію refresh token, вихід і перевстановлення.
- Порожній стан сну, сон, паузу, довгий/застарілий запис, офлайн та відновлення мережі; час і часовий пояс.
- Зміну сну з вебверсії або другого телефона, повторне відкриття застосунку й оновлення віджета.
- Додавання віджета, натискання картки, стан після logout, читабельність і приховування імені на заблокованому екрані.
- Прямі дії віджета: подвійний тап, конфлікт двох батьків, завершення/новий сон між показом і натисканням, 401 після виходу, офлайн, повільна мережа та оновлення після повернення в застосунок.

Web Push нагадування залишаються для PWA. Нативні APNs/FCM сповіщення ще не реалізовані. [Макет чотирьох станів віджета](design/sleep-widget-preview.png) показує орієнтир дизайну; фактичний вигляд треба підтвердити на пристроях.
