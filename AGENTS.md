# Інструкції для агентів

protsenkoHub — сімейний хаб для двох батьків: календар, покупки, задачі дітей, сон дитини та контакти. Дані однієї родини спільні. Інтерфейс українською.

Перед змінами в `apps/web` прочитайте [docs/project-context.md](docs/project-context.md) і скіл `.agents/skills/angular-developer/SKILL.md`. Скіл задає сучасний Angular 22. Цей файл фіксує, як саме він застосовується тут. Якщо скіл і сусідні файли розходяться, наслідуйте сусідні файли фічі й не перейменовуйте їх пакетом.

## Межі

- `apps/web` — Angular 22.2, standalone, zoneless, Signal Forms, `httpResource`, lazy routes.
- `apps/api` — NestJS 11, префікс `/api/v1`, JWT в httpOnly cookie `access_token`.
- `packages/shared` — спільні типи. Застосунки зараз дублюють власні моделі; не переносьте їх без окремого завдання.
- База — Postgres через Prisma. Локально Docker, на Vercel — Neon.
- Секрети, `.env`, `.env.local`, `.vercel` і `apps/api/prisma/*.db` не комітити й не друкувати.

## Angular у цьому репозиторії

- Компоненти standalone. `standalone: true` не пишіть: це поведінка за замовчуванням.
- `changeDetection: ChangeDetectionStrategy.OnPush`.
- Залежності беріть через `inject()`, не через конструктор компонента.
- Стан екрана — `signal` і `computed`. Читання списків — `httpResource`. Мутації — `ApiService`, після успіху `reload()` ресурсу.
- Нові форми — Signal Forms (`form`, `FormField`) з `@angular/forms/signals`.
- Шаблони: `@if`, `@for` з обов’язковим `track`, `@switch`. Для вичерпного union у `@switch` ставте `@default never`.
- Порожній компонент без проєкції — самозакривний тег: `<router-outlet />`.
- Селектор з префіксом `app-`.
- Імпорти лише на початку файлу. Вкладені `import()` у тілі функції не додавайте.
- У `switch` по union або enum гілка `default` має присвоювати значення в `never`.
- `effect` не використовуйте для запису стану, який можна виразити через `computed` або `linkedSignal`.

## Імена файлів

Скіл дозволяє імена без рольового суфікса. У цьому репозиторії суфікси вже є, тож нові файли повторюють теку, яку ви редагуєте:

- сторінка фічі: `calendar.page.ts` або, як у дитячих задачах, `children-page.component.ts`;
- сервіс фічі: `children.service.ts`, клас `ChildrenService`;
- модель: `children.model.ts` — інтерфейси й типи фічі, не всередині сторінки чи сервісу;
- конфіг: `sleep-guidance.config.ts`, `sleep.config.ts`, `auth.config.ts` — порогові числа й сталі рядки;
- тест: той самий базовий шлях і `.spec.ts`.

Пороги розрахунку, підписи й часовий пояс не лишайте літералами в алгоритмі. Новий тип кладіть у `*.model.ts` поруч із фічею, нове число правила — у `*.config.ts` тієї ж фічі.

Класи сторінок лишайте з суфіксом, який уже є поруч (`CalendarPage`, `ChildrenPage`, `LoginComponent`). Не змішуйте в одній теці `feature.ts` і `feature.component.ts`.

Сервіс фічі оголошуйте `@Injectable()` без `providedIn` і додавайте в `providers` сторінки. Глобальний лише `AuthService` (`providedIn: 'root'`).

## Стилі

- Глобальні токени, кнопки, поля, картки й типографіка — `apps/web/src/styles.scss`.
- Стиль компонента — лише те, що належить цьому екрану. Бюджет Angular: попередження 4 kB, помилка 8 kB на стилі компонента.
- Кнопки `.button` і поля `.field input`, `.field select` мають висоту 44px і радіус 12px. Новий контрол на екрані має ту саму висоту.
- Кольори беріть зі змінних `:root` (`--forest`, `--clay`, `--paper`, `--ink`). Не вводьте окрему палітру на сторінці.
- Tailwind у проєкті немає. Не підключайте його для одного екрана.
- Анімації — CSS. Пакети `@angular/animations` не додавайте.

## Продукт

- Текст інтерфейсу українською. Дати й порівняння рядків — локаль `uk`.
- Задачі дітей живуть на `/app/children`, але API лишається `/api/v1/solomiya/tasks`. Сон — `/app/sleep` і `/api/v1/solomiya/sleep`. Ці API-шляхи не перейменовуйте.
- Реєстрація створює нову родину. Другий акаунт сам не приєднується до першої.
- Активний сон читається з бази. Повторний старт і перезавантаження сторінки не змінюють `startedAt`.

## Перевірка

З кореня репозиторію:

```bash
npm run typecheck
npm test
```

Після зміни інтерфейсу перевірте сценарій у браузері: порожній стан, помилку й основну дію. Локальний API потребує Postgres з `docker compose up -d`.
